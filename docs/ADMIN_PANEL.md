# Admin Panel - Руководство по использованию

## 🔒 Что было сделано

### Проблема
Посты удалялись, но восстанавливались снова из-за скрипта `import-media.js`, который можно было запустить вручную или автоматически. Это также вызывало высокую нагрузку на систему.

### Решение
1. ✅ **Отключен старый скрипт импорта** - переименован в `import-media.js.disabled.BY_ADMIN`
2. ✅ **Создана админ-панель** - веб-интерфейс для управления импортом медиа
3. ✅ **Добавлена защита** - только admin может использовать панель (middleware `requireAdmin`)
4. ✅ **Ручное управление** - админ сам выбирает какие папки импортировать

---

## 🎯 Как использовать админ-панель

### 1. Вход в систему
- Войдите под учетной записью **admin**
- Пароль можно найти в `.env` файле или сбросить через скрипт `manage-users.js`

### 2. Открытие панели
- После входа в шапке появится кнопка ⚙️ (рядом с 📷 и 👤)
- Нажмите на неё чтобы открыть админ-панель

### 3. Импорт медиа из папок

#### Шаг 1: Scan (Сканирование)
- В панели видны все доступные папки из `/opt/media/files/`
- Нажмите **🔍 Scan** напротив нужной папки
- Система просканирует файлы и добавит их в очередь импорта
- Будет показано количество найденных файлов

#### Шаг 2: Import (Импорт)
- После сканирования нажмите **📥 Import**
- Система создаст посты из файлов в очереди
- Файлы группируются по дате (в пределах 24 часов = 1 пост)
- Максимум 20 файлов в одном посте

### 4. Статус очереди
В разделе "Import Queue Status" видно:
- **Total** - всего файлов в очереди
- **Pending** - ожидают импорта
- **Done** - уже импортированы
- **Errors** - ошибки при импорте

### 5. Дополнительные действия
- **🔄 Refresh Folders** - обновить список папок
- **🔄 Refresh Queue** - обновить статус очереди
- **🗑️ Clear Queue** - очистить очередь (требует подтверждения)

## 🔧 Технические детали

### API Endpoints
Все endpoints требуют admin авторизации:

```
GET    /api/admin/media/sources      - Получить список папок
POST   /api/admin/media/scan         - Сканировать папку
POST   /api/admin/media/import       - Импортировать файлы
GET    /api/admin/media/queue        - Статус очереди
DELETE /api/admin/media/queue        - Очистить очередь
```

### Конфигурация импорта
Настроено в `/opt/cosmogram/routes/admin.js`:

```javascript
batchSize: 20,                // макс. файлов в посте
groupByMinutes: 1440,         // окно группировки (24 часа)
thumbSourceDir: '/opt/media/thumbs/',
uploadDir: 'uploads/images',
videoDir: 'uploads/videos'
```

### Безопасность
- ✅ Только admin роль имеет доступ
- ✅ JWT token проверка на каждом запросе
- ✅ Старый CLI скрипт отключен
- ✅ Нет автоматического импорта - только ручной

## ⚠️ Важные замечания

1. **Не запускайте старый скрипт** `import-media.js.disabled.BY_ADMIN` - он отключен намеренно
2. **Сканирование перед импортом** - всегда сначала делайте Scan, потом Import
3. **Повторный импорт** - если папка уже импортирована, будет показано количество файлов
4. **Нагрузка на систему** - импорт больших папок может занять время, следите за статусом

## 🐛 Решение проблем

### "Failed to load folders"
- Проверьте что папка `/opt/media/files/` существует
- Проверьте права доступа: `ls -la /opt/media/files/`

### "Scan failed"
- Убедитесь что в папке есть медиафайлы (jpg, png, mp4, etc.)
- Проверьте доступность exiftool: `which exiftool`

### "Import failed"
- Проверьте что сканирование было выполнено перед импортом
- Смотрите логи сервера: `journalctl -u cosmogram -n 50`

### Посты не создаются
- Проверьте что админ пользователь активен в БД
- Смотрите логи на наличие ошибок

## 📊 Мониторинг

### Логи сервера
```bash
journalctl -u cosmogram -f
```

### Статус очереди (из CLI)
```bash
sqlite3 /opt/cosmogram/data/media.db "SELECT status, COUNT(*) FROM import_queue GROUP BY status;"
```

### Количество постов
```bash
sqlite3 /opt/cosmogram/data/media.db "SELECT COUNT(*) FROM posts;"
```
